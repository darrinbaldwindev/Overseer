# AgentOS Demonstration Readiness Gate

## Purpose
Provide a hard gate before an AgentOS workflow is promoted from concept/demo material into public validated marketing or production-facing claims.

## Gate levels

### GREEN — CONCEPT READY
- Workflow is coherent and visually understandable.
- All simulated activity is explicitly identified as synthetic/illustrative.
- No unsupported customer, performance, integration or production claims.

### GREEN — DEMONSTRABLE
All of the above, plus:
- The underlying workflow can actually be executed in a controlled environment.
- Actual system events support displayed states.
- Proposal, approval, execution and result states are distinguishable.
- Evidence can be inspected by an authorised reviewer.

### GREEN — VALIDATED
All of the above, plus:
- Relevant users/customer evidence supports the problem and workflow.
- Integration feasibility is established for the stated environment.
- Outcomes are supported by evidence rather than illustrative metrics.
- Claim wording has been reviewed against the evidence boundary.

### GREEN — PRODUCTION
All of the above, plus:
- Production implementation has passed applicable security, quality, assurance, governance and operational gates.
- Real permissions and execution controls are enforced.
- Monitoring, failure handling and rollback/safe-state behavior are established where applicable.
- Release authority is explicitly recorded.

## Automatic blockers
A promotion must stop if any of the following occurs:
- Fabricated activity or evidence.
- Character claims that do not correspond to recorded activity.
- Proposed work presented as completed work.
- Unverified customer testimonial, logo, metric or outcome.
- Unsupported third-party integration/model claim.
- Assurance displayed as GREEN without required evidence.
- Production wording used for concept-only capability.
- Marketing creative contradicts the canonical UI, character or claim guardrails.

## Review record
Each promoted asset/workflow should retain:
- Evidence status.
- Source workflow/version.
- Date reviewed.
- Reviewer/authority.
- Known limitations.
- Approved claim boundary.

## Principle
**Show what exists. Label what is proposed. Prove what is claimed.**
