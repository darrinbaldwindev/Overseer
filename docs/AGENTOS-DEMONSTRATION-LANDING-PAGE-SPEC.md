# AgentOS Demonstration & Landing Page Specification

## Status
Marketing/product specification. No production website implementation is authorised by this document.

## Objective
Define a single evidence-safe demonstration journey that explains AgentOS quickly while showing the breadth of the product without turning the homepage into a feature catalogue.

## Core message hierarchy
1. **AgentOS** — the governed AI workforce / operating layer.
2. **AI Team** — Willow, Isla, Jack and Henry show the human-readable workflow roles.
3. **Intelligence** — AgentOS can coordinate available AI providers, specialist agents and appropriate intelligence sources according to capability, policy, entitlement and task needs.
4. **Interfaces** — Simple, Essentials and Tech Head are presentation modes over the same governed capability model.
5. **Work** — the visitor sees a real workflow moving from request → plan → execution → challenge → assurance → result.

## Recommended page journey

### 1. Hero
- Clear AgentOS identity.
- One concise value proposition.
- Primary CTA: See how it works.
- Secondary CTA: Explore the AI team.
- Avoid unsupported performance, savings or autonomy claims.

### 2. The problem
Explain that users increasingly have access to many AI systems but still need to decide which intelligence to use, coordinate work, manage approvals, verify results and maintain control.

### 3. The AgentOS answer
Show AgentOS as the coordination/control layer rather than another isolated chatbot or single AI model.

### 4. The AI team
Show the canonical roles:
- Willow — Plan and research.
- Isla — Execute and coordinate authorised work.
- Jack — Challenge, check and improve.
- Henry — Independently assure and verify.

Character activity must reflect recorded/demo activity; never imply that a character performed work that did not occur.

### 5. One workflow demonstration
Use a concrete, bounded workflow. The demonstration should visibly show:
1. User request.
2. Willow's plan.
3. Intelligence selection/routing.
4. Isla's authorised execution.
5. Jack's challenge/check.
6. Henry's independent assurance.
7. Evidence/result.
8. User approval where required.

The workflow must be genuinely demonstrable or clearly labelled as CONCEPT.

### 6. Three ways to use AgentOS
Present:
- SIMPLE — Keep it simple.
- ESSENTIALS — See what matters.
- TECH HEAD — See everything.

Emphasise that these are presentation modes, not different products or permission levels.

### 7. Universal audience bridge
Show that the same governed operating model can support personal, family, student, developer, creator, freelancer, professional and business workflows. Avoid claiming validated demand for any audience until evidence exists.

### 8. Trust/control section
Explain approvals, permissions, security, quality, cost, speed, governance, evidence and independent assurance in plain language. Do not claim these controls are production-ready unless implementation evidence supports it.

### 9. Intelligence optimisation
Explain the philosophy: use appropriate intelligence for the job, rather than forcing every task through one model/provider. Where evidence supports it, AgentOS can balance capability, quality, cost, speed and entitlement.

### 10. CTA
Invite the visitor to explore a workflow, request access, join a validation programme or learn more depending on actual product stage. Do not imply a generally available production product before launch gates are met.

## Demonstration rules
- Every visible capability claim has an evidence status.
- Demonstration data must be clearly synthetic unless real authorised data is being used.
- No fake customer logos, testimonials, metrics, integrations or outcomes.
- No fabricated model-provider activity.
- No UI element may imply an action occurred when it was only proposed.
- Approval states must be visually distinct from completed actions.
- Evidence/result views should be reachable from the demonstration.

## Visual direction
Use the canonical AI Team visual system and UI mode specification. The experience should feel premium, calm, trustworthy and human-centred rather than futuristic or gimmicky.

## Acceptance gate
The landing experience is ready for validation only when a first-time visitor can understand what AgentOS is, see how the AI team works together, understand the three interface modes, and distinguish demonstrated capability from future/validated capability without relying on unsupported claims.
