On first receipt of this handoff:

1. Read the full vertical batch doctrine above.
2. Fresh-scan your own project repository/workstream before trusting previous chat state.
3. Locate any existing canonical project control issue, batch file, PR, or durable log.
4. If no existing project vertical batch file exists, create:
   `.overseer/batches/VERTICAL-EXECUTION-BATCH.md`
   unless the repository already has a better established canonical batch path.
5. Reconcile/create a full vertical batch from fresh evidence.
6. Execute as much safe, useful work as possible immediately.
7. Verify with exact repository/test/CI/runtime/research evidence appropriate to the project.
8. Fresh-scan again before replenishing.
9. Replenish the same batch file before returning control.
10. Log significant progress durably in the project's established control issue/log.
11. Surface portfolio-significant blockers or architectural conflicts to ChatGPT Overseer / `darrinbaldwindev/Overseer` issue #49.
12. From then on, owner messages `cont`, `continue`, `continue autonomously`, or `continue autonomously vertically` automatically trigger the entire cycle again.

Do not create a duplicate scheduler, authority layer, registry, mission ledger, Green system, PRS system, persistence layer, or source of truth to implement this doctrine.
