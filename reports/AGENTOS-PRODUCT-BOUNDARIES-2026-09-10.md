# Product and commercial implementation boundaries

This is an implementation handoff, not approved pricing or an activation plan.
Current owner instruction supersedes earlier $29-default wording. Currency and
final capacity quantities are not specified; do not invent them.

| Requirement | Existing integration point | Required behavior and evidence |
|---|---|---|
| Free / $39-year challenger / $99-year Operator / BYO | Existing capability passport and routing/policy metadata | Keep $39 experimental; separate entitlement from authority and provider billing |
| Limited $39 Night Shift | Existing scheduler and autonomy policy | Bounded trial capacity under the same opt-in, authority, risk, budget, approval and assurance gates |
| Broader $99 capacity | Same scheduler, reservations and worker registry | Materially more delegation, schedules, concurrency, persistence, integrations, capacity and recovery; quantities need validation |
| Universal safety | Canonical Green/PRS and permissions | Never advertise stronger trust only for paid users; no tier bypass or purchased approval |
| Time windows | Existing scheduler tick and pickup eligibility | Window changes WHEN only; test cross-midnight/DST, paused-at-pickup, claim expiry and exhausted budget |
| Downgrade/upgrade | Existing task and reservation lifecycle | Re-evaluate new admission; preserve already spent budget/evidence, never resurrect stale claims or expand existing task authority |
| Morning Brief | Read projection of canonical persisted receipts/results/ledger | Distinguish complete, blocked, interrupted, unknown; no second ledger; no completion from worker claims alone |
| Everyday/Essentials/Tech Head | Existing chat view | Preserve large conversation and composer in all modes; reveal details progressively without a second authority state |
| Willow / Isla / Jack / Henry | Existing task lifecycle and conversation events | Brief introductions at real planning, execution, permission and assurance moments; active users can meet all in week one; no fabricated verification |
| Thirty-day nurture | Existing preferences and scheduler | Contextual, dismissible education; days are not feature unlock gates |
| Post-day-30 prompt | Fresh demonstrated value event + preferences | No event means no prompt; a weekly interval is only a hypothesis, never sufficient reason |
| Referral aha | Actual useful result and user feedback | A deterministic dry-run completion is not proof a general user goal was achieved; suppress on failure, partial/uncertain work or negative feedback |
| Member/creator attribution | Separate relationship types in existing commercial model | Never convert members to creator affiliates silently; no automated invitations, incentives or tracking activation |

Observed conflicts requiring reconciliation:

- Main marketing briefs already describe the $39 challenger; older commercial
  reconciliation and autonomy branches retain the earlier $29 ladder. Treat these
  as historical/control assumptions, not simultaneous production offers.
- Wording about paid “stronger assurance” must mean more capacity or recovery
  convenience, never weaker mandatory checks at Free or $39.
- “Three active days” alone in a referral test candidate does not prove an aha
  moment. Require a real value reason in addition to any activity threshold.
- The current local chat accepts arbitrary text but returns a fixed bounded-check
  explanation. It is not a useful general AI assistant merely because status is
  COMPLETE. Do not show Night Shift/referral success prompts based on that alone.
- Four-role introduction is feasible through existing events, but Henry must not
  appear to certify a task before independent assurance exists.

No entitlement, pricing, notification, reward, billing or production configuration
was changed. Runtime Night Shift, Morning Brief and nurture integration remain
implementation work, not proven commercial capabilities.
